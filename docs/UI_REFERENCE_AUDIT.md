### CCBABY 建議方案（待實作）

1. 店主現場拍攝 → 上傳自有 YouTube → 複製分享連結 → 在新增／編輯商品貼入「商品影片連結（選填）」→ 儲存；第一版每款一支
2. 商品卡於價格與選規格操作附近獨立一列放「看影片」，詳情照片／說明附近也提供入口，沿用 CCBABY 色票與細線播放圖示；空白完全省略，手機不把標題與操作擠在同列
3. 點擊後才建立播放器，Shorts 用適合手機的 9:16 視窗；關閉後卸載播放器，回原商品及原捲動位置，保留顏色、尺寸、數量與相片張數。商品列表不預先載入 100～200 個播放器
4. 先支援 YouTube Shorts 與其分享網址；若接受一般 watch／youtu.be 網址，不能只靠網址判定直橫，須提供簡單比例選擇或明確採直式預設。IG、Vimeo、自動上傳 YouTube、直接上傳原始影片及多影片排序先不列入建議首版
5. 採用 YouTube 嵌入播放器，始終提供「在 YouTube 開啟」備援；不把自動播放成功當成前提，也不聲稱能移除 YouTube 廣告、品牌或全部相關影片

YouTube 可選「公開」或「不公開」，並保持允許嵌入；不公開影片仍可由取得連結者轉傳，不能當會員專屬素材。[可見度說明](https://support.google.com/youtube/answer/157177?hl=zh-Hant)、[嵌入與隱私加強模式](https://support.google.com/youtube/answer/171780?hl=zh-Hant)

### 與現行程式的銜接範圍

- 管理：apps/admin-web/app.js 增選填欄位、檢查與預覽入口；product-draft.js 白名單保存連結，保留現有離開保護及照片／進價流程
- 共用驗證：另建影片網址規則，使用 URL 解析及精確 HTTPS 主機白名單，取合法影片 ID 後自行組成 embed URL；不接受任意 iframe／HTML，不直接沿用第三方的網址比對式
- 資料：建議新增公開商品欄位 videoUrl，與店主私有採購來源 sourceUrl 分開。cloud/core.mjs 納入驗證、商品保存及受保護 catalog／bootstrap；沿用現有私有 JSONB 與 revision 提交，依目前架構推估無需新增雲端資料表／Storage。本機 server/api.mjs／store.mjs 需對應欄位、無損升級與備份還原
- 相容：舊商品缺欄位視為無影片；舊客戶端／匯入請求省略欄位時保留現值，明確空字串才清除。評估 domain/product-transfer.mjs 的 CSV／XLSX 往返，避免複製商品漏掉連結；不改既有預購快照與採買計算
- 客戶：apps/customer-web/app.js 的 renderGrid／showProduct 接入口及獨立播放器生命週期，style.css 處理小螢幕、安全區與橫直式；不能只做一個會丟失原商品選擇的共用 modal 替換
- 本機播放限制：server/index.mjs 目前 CSP 只允許 self，且 Referrer-Policy 為 same-origin；實作需精確允許指定 YouTube frame 來源，並針對播放器設定可傳送來源 origin 的 referrerpolicy，保留其他限制。YouTube 缺 HTTP Referer 可能出現錯誤 153；正式 Pages 標頭也需另行核對，不能用本機標頭推定正式狀態。[官方播放器說明](https://developers.google.com/youtube/iframe_api_reference)、[參數與 rel 限制](https://developers.google.com/youtube/player_parameters)

後續實作驗收須含：連結保存／清除／草稿／重開／匯出入、舊資料與錯誤網址、未點擊不請求 YouTube、關閉即停止聲音、規格與相片／捲動位置保留、播放失敗可返回或開 YouTube、320／390／768／1440px，以及既有 LINE 登入、購物車保存、送單／追加、本人及管理查單。另以實體 iPhone LINE 內瀏覽器及 Safari 確認播放、全螢幕與返回；本次沒有執行這些尚未實作的驗收。
