# 本機測試版操作說明

0.3.11 進價也可在「新增／編輯商品」填：商品進價（選填）→ 填韓幣單件進價與換算匯率 → 查看台幣 → 儲存。留白可直接上架；與採買清單共用資料。不同規格進價會列出明細，未修改保留原價，明確填寫套用有效規格；草稿與原版本保存，衝突按「載入最新進價，保留其他欄位」。


0.3.10 商品草稿：新增／編輯商品時即時暫存在同一分頁；切頁回來可繼續，重新整理或到期重登後自動恢復。按「稍後繼續」／X／Esc，確認後保留草稿；重開同款或新增商品繼續。「放棄草稿」需確認，儲存商品成功則自動移除。中斷上傳的原圖需重新選取，按「確認照片已齊」後才可儲存；不會自動上架草稿，關閉分頁可能清除暫存。

0.3.9 刪除操作：客戶預購 → 查看明細 → 刪除預購 → 確認摘要，輸入完整預購編號及刪除原因 → 確認刪除整份預購。按「保留預購」可返回；有採購／缺貨／分配紀錄時先處理再刪除。客戶重新整理後看不到原訂單，內部保留歷史，新送單產生新編號。


0.3.8 進價操作：活動與設定 → 韓幣進價換算 → 填「1 韓元等於多少台幣」並儲存 → 採買清單 → 記錄進價／採買 → 填韓幣單件進價，查看台幣換算與售價 → 儲存。改設定不回寫舊成本，必要時按「改用目前設定匯率」。匯出 Excel 含客戶預購明細、採買彙總與進銷總覽；未填成本件數獨立顯示。


0.3.6 客戶相簿：打開商品 → 在主圖左右滑動切照片，也可點縮圖 → 點照片放大 → 返回商品保留照片位置。左上角顯示張數，滑動不會更動規格。


0.3.5 定價操作：商品編輯 → 填基本售價與尺寸列表 → 在「各尺寸加價」填金額（不加價填 0）→ 查看各尺寸售價 → 儲存。例如基本 590、2XL 加 50、3XL 加 100，售價為 590／640／690。


0.3.4 照片操作：商品管理 → 編輯／新增 → 多選或拖入照片 → 等待各張完成 → 拖曳或左右排序 → 儲存商品。第一張是封面；預設相簿獨立，必要時勾選「依顏色切換照片」並指定對應。原檔每張最多 20 MB，自動縮圖，上傳中或失敗先處理再儲存。

## 1. 兩個獨立入口

| 入口 | 本機網址 | 登入 |
|---|---|---|
| 客戶選物頁 | http://127.0.0.1:4173/ | 點「會員登入」，選擇清楚標示的本機測試會員 |
| 店主工作台 | http://127.0.0.1:4174/ | 唯一一組管理帳密 |

正式網站尚未上架；正式前後台代管位置，待使用者另行指定。
本機只監聽 127.0.0.1，不能讓另一台手機直接用這個網址連線。
目前提供桌面瀏覽器與手機尺寸的版面測試，不設定公開隧道或外部主機。

## 2. 啟動

需要 Node.js 24 以上，目前驗證使用 24.14.1。沒有第三方 npm 執行依賴，不需要先 npm install。

在專案根目錄執行：

```sh
npm start
```

同一個 Node 程序會啟動兩個 HTTP 入口，各自只提供自己的前端與 API 範圍。
需要修改後端時可改用 `npm run dev`；它會重啟後端，瀏覽器畫面仍需重新整理。
若已經有本次啟動的服務，直接使用網址，不要同時再啟動佔用相同連接埠的程序。
在啟動服務的終端按 Ctrl+C 可停止。

## 3. 管理員帳密

- 唯一管理帳號是 `hannah`。
- 首次啟動時產生隨機測試密碼，存放於根目錄 `.local/admin-credentials.txt`。
- 該目錄及檔案限制本機存取，且已被 .gitignore 排除。
- Markdown、前端與公開設定不保存密碼。
- 後台「活動與設定」可更換密碼；更換後舊登入失效，初始明文測試憑證檔會刪除。
- 正式上線的帳密與秘密管理設定尚未建立。

## 4. 客戶測試流程

1. 打開客戶入口，可先看本期商品、分類及搜尋。
2. 點「會員登入」，選擇「測試訪客」或其他虛構會員。
3. 點商品，選顏色、尺寸／規格及數量，再加入購物車。
4. 打開購物車，填聯絡姓名與手機，按「送出預購・目前不用付款」。
5. 成立後顯示預購編號，從「我的預購」查明細、追加或於結單前調整數量。
6. 聯絡及收件資料可在「我的預購」編輯；收件資料可稍後補齊。

同規格的購物車會合併數量。相同會員的追加會歸入同一份本期預購。
草稿依測試會員隔離並存在瀏覽器；已送出資料保存在 SQLite，重啟服務後仍可查詢。

## 5. 後台測試流程

- **工作總覽：**看預購客戶、有效件數、預估金額、上架商品與採買進度。
- **商品管理：**單筆新增／編輯、分類、規格價格、上下架及上傳圖片。
- **CSV 匯入：**下載範本、貼入或選檔、預覽錯誤，確認後才寫入；可由 Excel 另存 UTF-8 CSV 使用。
- **客戶預購：**按人看商品、規格、數量、聯絡與收件資料，複製分貨明細。
- **採買清單：**按商品規格加總，記錄累計已買、確認缺貨與備註；手機版為逐項卡片。
- **手動分配：**先在採買清單記錄數量，再於客戶明細指定分配給該客戶的買到／缺貨件數。
- **匯出 Excel：**同一檔案包含「客戶預購明細」與「採買彙總」兩張工作表。
- **活動與設定：**改活動名稱、台灣時間截止時間、目前階段、更換管理密碼及下載 JSON 資料備份。

把活動切離「開放預購」，會阻擋客戶新增與修改，並建立結單快照。
已採購或已記缺貨的品項，客戶不能自行減量而破壞採購結果。
本機尚無店主直接改客戶需求數量的介面；這類異動目前待補。

## 6. 示範資料與實作界線

- 預載 120 款虛構選物、6 個類型、虛構會員與預購。
- 商品圖是本專案程式產生的原創 SVG 示意，沒有沿用參考站商品照片。
- 品牌名稱為 CCBABY；Logo、配色與分類目前為本機示範方案，正式素材待使用者提供。
- 正式 LINE 登入尚未串接，不能把測試會員登入視為真實身分驗證。
- 測試會員選擇功能只用於本機預覽，不可直接作為正式公開網站。
- 本版處理單一期活動，沒有次年活動複製、跨年度歷史介面或多活動切換。
- 支援 .xlsx 匯出及 CSV 匯入，尚未支援直接匯入 .xlsx。
- JSON 資料備份有圖片參照，不包含圖片實體檔；完整備份還原流程尚未完成。
- 圖片可上傳及儲存，本版尚未提供完整的刪圖／拖曳排序管理。
- 付款與交付依原定方式在 LINE 人工聯絡，網站沒有結帳或金流。

完整目標與本機進度對照見 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。

## 7. 程式與資料位置

```text
apps/customer-web/         客戶端 HTML／CSS／JS
apps/admin-web/            管理端 HTML／CSS／JS
server/index.mjs          兩個本機入口、靜態檔與存取邊界
server/api.mjs            登入、商品、預購、採買、分配與匯出 API
server/store.mjs          SQLite 結構與示範資料
server/xlsx.mjs           不含巨集與公式的 Excel 寫出
server/art.mjs            原創 SVG 商品示意
domain/rules.mjs          數量、開團、聯絡資料及 CSV 規則
tests/app.test.mjs        暫存資料庫與臨時連接埠的整合測試
.local/                   被排除的私有本機資料
├─ preorder.sqlite        正式讀寫的本機測試資料庫
├─ admin-credentials.txt  初次產生的測試帳密
└─ uploads/               後台上傳的商品照片
```

SQLite 是本機測試版的資料權威來源；localStorage 僅保存該會員購物車草稿。
測試使用另一份臨時資料庫，不會清空使用者目前的 .local 資料。
