## 0.3.30 商品詢問網址縮圖（D-51）

客戶照原本按「用 LINE 詢問這款」→ 訊息帶商品編號、名稱與一個預覽網址 → 在 LINE 確認傳送。店主可由網址預覽辨識首圖；點網址仍進原商品視窗。後台「複製連結」也使用相同預覽形式，不要求額外貼照片。首圖／名稱變更後，重新產生的連結自帶新版本；舊 hash 仍可使用

預覽只公開上架商品編號／名稱／首圖，完整選購仍需 LINE 登入；有照片才提供商品圖。LINE 縮圖受平台設定、抓取與快取影響，沒有縮圖時仍可點網址；手機官方帳號 App 與電腦後台的實際收訊顯示尚待驗收，不保證所有版本均顯示。

來源：[LINE 網址預覽 FAQ](https://developers.line.biz/en/faq/)、[開啟官方帳號並預填文字](https://developers.line.biz/en/docs/messaging-api/using-line-url-scheme/#opening-a-chat-screen-with-a-line-official-account)、[Supabase HTML 限制](https://supabase.com/docs/guides/functions/limits)。本次不操作 LINE 原生設定或替客戶傳訊息

網站保留原登入、購物車、預購成立／追加／修改、採購與分配流程；不新增付款回報、實收／退款紀錄、24 小時自動取消、付款順序排序或採購付款閘門。付款、退款與寄件順序由店主在 LINE 人工核對及作業，預購資料成立不代表已付款。

使用者提供新版歡迎詞作為網站內容依據；本次未操作 LINE 原生歡迎詞、關鍵字或選單，assets/line-official/copy.json 與下方 11/08 表格為歷史實際設定，不代表此次已同步原生設定

## 0.3.24 訂單通知（D-45，啟用狀態見 HANDOFF）

成功送出預購／追加時，系統先保存訂單與通知，再嘗試發送官方帳號訊息；LINE 失敗不影響訂單成立。後台「客戶聯繫」顯示當月額度與通知狀態，使用 LINE 登入會員身分指定對象，不要求新客再傳碼。

到台操作：先完成本人買到／缺貨分配並將活動設為「商品已到台」→ 開啟該客戶 → 選「到台通知」→ 核對文字 →「確認並發送 LINE」→ 頁內確認收件人與預購 →「確認發送給這位客戶」。每位客戶分開操作，不提供一鍵群發。

額度不足或發送失敗：保留文字與圖卡 →「複製訊息，改用人工傳送」→ 在 LINE 官方帳號核對預購編號與聊天室後人工傳送 → 確認聊天室並標記「我已在 LINE 人工傳送」。標記後停止相同通知自動重試；如果先前結果不明，人工傳送前先查看聊天室，避免重複。

店主自行升級 LINE 方案後按「更新資料」取得新額度；系統不代購方案。API 接受發送不等於已讀，人工傳送標記不等於已付款。採購進度與匯款聯繫仍保留原人工方式，完整聊天收件匣未製作。

正式後端發訊憑證已依明確同意簽發保存並啟用，店主 API 核對剩餘 200/200；若未來設定失效，後台會顯示原因並提供人工備援。尚未向真實客戶發測試／歷史訊息，手機收訊仍待驗收。發送規則、失敗處理與重試以 line-notifications／line-delivery 及 tests/line-notifications.test.mjs 為準。

更新：2026-11-09｜版本 0.3.24（網站已發布，指定 LINE 通知已啟用）

## 0.3.19 歷史開聊方式（新客已由 0.3.24 取代）

入口包含商品「用 LINE 詢問這款」、購物車協助、送單成功及「我的預購」內的詢問按鈕。

1. 登入會員點選入口，後端只替本人建立一次穩定聯繫碼
2. 畫面顯示聯繫碼、預填內容與 LINE 連結，商品詢問附商品編號／名稱，預購聯繫附預購編號
3. 客戶開啟 LINE，必要時先加入官方帳號，確認後自行按下傳送
4. 店主收到訊息，以聯繫碼對照網站會員，再人工核對聊天室

同一客戶後續詢問與預購沿用相同代碼。聯繫碼不是登入密碼、不賦予網站權限，也不能作為帳號授權憑證。點開入口不代表已傳訊息或已加好友，網站不自動更改聯繫確認狀態。

LINE 官方 URL scheme 支援手機 iOS／Android，官方文件說明不支援 PC；因此也提供「複製詢問文字」與手機搜尋官方帳號 @445yxcey 的備用方式。未直接操控實體 iPhone，連結預填及站內操作於隔離瀏覽器驗證。

## 四個服務階段

| 通知 | 可準備的條件 | 內容與限制 |
|---|---|---|
| 預購確認與感謝 | 有效預購有正數明細 | 預購編號、品項／規格、件數、售價快照與預估商品小計；說明代購不保證現貨，下單後 24 小時內人工確認付款再採購 |
| 採購進度 | 此客戶的明細已分配買到或確認缺貨 | 分清全部買到、部分買到、缺貨與待確認；其他客戶的採買數或尚未分配的總量不當作本人的結果 |
| 到台通知 | 活動為「商品已到台」，且本人有分配買到的品項 | 告知已分配買到的件數；待採買與缺貨分開說明，再確認運費與交付 |
| 匯款聯繫 | 有效預購有正數明細 | 列完整預購商品小計，提醒下單後 24 小時內付款，運費、收款資料及最終總額由店主在 LINE 核對後提供 |

所有訊息都可先改寫，再複製至官方帳號原生的個別聊天室。確認人工傳送後，才在網站按「我已在 LINE 人工傳送」。此標記只表示店主自己的作業紀錄，不表示 LINE 送達／已讀，更不表示付款。

人工核對聊天室前可以準備圖卡與文字，但不能標記已通知。通知紀錄使用版本及內容簽章；預購、採購分配或相關階段變動時，舊通知會重新列為需確認，舊畫面不能覆蓋新版本。已刪除或數量為零的預購不列通知。

## 免費一對一方式

網站只準備 LINE 連結、文字與圖片，不呼叫 Messaging API Push，不替店主傳訊息。依 LINE 官方費用說明，官方帳號原生一對一聊天不列入訊息費用；是否已有其他月費或加購，仍以店主原帳號設定為準，本次未變更 LINE 方案。

來源：[LINE 一對一聊天與訊息費用](https://tw.linebiz.com/column/budget-auto-count/)、[官方帳號聯繫限制](https://help.line.me/official_account_tw/web/pc?contentId=200001206&lang=zh-Hant)

- 雲端使用既有私有 JSONB：customers[].contact_code、customerCare、orderNotices；仍由 revision 原子提交與每次角色驗證保護，沒有新的公開資料表或訊息密鑰
