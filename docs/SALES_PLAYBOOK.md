# 瀏覽資料與銷售運用

更新：2026-11-08｜版本 0.3.18

## 已確認方向

使用者要求保存研究並優化兩個方向：

1. 後台將瀏覽紀錄轉成店主下一步與官方帳號對話準備
2. 後台提出客戶商品排序建議，由店主決定是否套用

使用者明確選擇「先由後台提出排序建議，店主決定套用」。不是個人化自動排序；未套用前客戶頁維持原順序，套用後所有客戶共用同一順序。

本文件保存研究、操作方法及規則理由；需求主檔仍為 SPEC，完成與部署狀態以 IMPLEMENTATION_STATUS／HANDOFF 為準。

## 研究：專業團隊如何使用

| 觀察 | 專業工作 | 套用本案的方式 |
|---|---|---|
| 進站、商品、加購、成立預購 | 找每段轉換的流失與操作阻礙 | 先查送單失敗，再了解加購未送出的情況 |
| 重複看商品、切規格、查說明 | 提出資訊不足的假設，再向顧客或操作測試求證 | 準備實量、材質、照片、預購規則；不把操作直接當心理結論 |
| 只瀏覽、已加購、已有預購 | 用不同強度的協助與訊息 | 瀏覽客先準備資訊，加購客可詢問是否需協助，已有預購先服務現有明細 |
| 商品看的人多，但加購或預購少 | 檢查資訊與價格疑慮 | 不因瀏覽數高就認定暢銷或增加實際採買 |
| 看的人少但已有正式需求 | 考慮增加介紹與曝光 | 店主可參考建議調整排序，觀察後續變化 |
| 多品項一起買 | 研究合理搭配與每單件數 | 後續可做穿搭介紹；本版不自動產生搭售或折扣 |
| 調整後訂單增加 | 驗證效果是否來自調整 | 同時考慮活動截止、來源與客群，前後比較不直接等於因果 |

主要來源：

- [Google 漏斗探索](https://support.google.com/analytics/answer/9327974?hl=en)：按固定步驟與一致人數口徑觀察轉換

## 第一版：店主下一步

入口：管理「瀏覽紀錄」→ 選客戶 →「下一步建議」

| 條件 | 建議 |
|---|---|
| 目前有效預購已有確認缺貨分配 | 優先核對品項與可告知的採購結果 |
| 近期送單失敗、目前沒有有效預購 | 先核對正式預購，再詢問操作是否需要協助 |
| 已有預購、失敗晚於預購更新且未見後續成功 | 核對是否有未列入的追加需求 |
| 近期加購、目前未預購 | 準備商品與規格，必要時做簡短詢問 |
| 選過規格或多次回看 | 準備尺寸、材質與照片，等待合適的服務機會 |
| 已有有效預購 | 先服務現有預購，避免再次要求完成同一筆 |
| 活動未開放、沒有近期訊號或沒有紀錄 | 保留觀察，不直接要求新增預購 |

近 3 天／超過 7 天等為第一版工程規則，不是通用銷售定律。清單使用當期預購、最近活動、加購及回訪整理優先序；明細才加入已載入的送單與規格操作。時間軸尚有分頁時顯示資料範圍，不能把未載入的操作當不存在。

每次讀取瀏覽紀錄，後端一併提供最新的活動狀態及最小預購摘要，避免沿用舊畫面狀態。對話草稿可修改、複製，修改只保留當前畫面。

### 人工官方帳號對話

1. 看建議與事實依據，先核對已成立預購
2. 準備關注商品的實際資訊，不推測客戶心理
3. 若本來已有可聯繫關係，在官方帳號核對客戶與過往對話
4. 修改草稿，提供一個明確的協助方式，再人工傳送
5. 觀察回應與後續正式預購；同時留意客戶是否不希望收到聯繫

例：有尺寸疑問時，可說「如果有尺寸想確認，可以告訴我，我可以幫你對照商品資訊」。避免說「我看到你一直看、怎麼還沒下單」。不得自行捏造版型、折扣、供貨保證或期限。

系統只開啟 LINE 官方帳號管理首頁，不會定位或假裝已配對特定聊天室，也不會傳訊息。網站未串 Messaging API，沒有好友、封鎖、訊息送達或對話內容資料。

## 第一版：店主審閱商品排序

入口：管理「商品排序」

1. 選 7／30／180 天的觀察期間，預設 30 天
2. 看目前順序、商品依據及建議名次
3. 按「載入資料建議」只建立草稿；可再上移、下移或置頂
4. 按「套用此順序到客戶頁」才保存；客戶下次載入使用新順序
5. 可載入上次排序或原始上架順序，確認後再次套用

### 可解釋規則

`分數＝本期有效預購人數 × 6＋所選期間曾加購人數 × 3＋min(所選期間瀏覽人數, 10)`

- 每款各訊號按不重複客戶計數；同一人多次重新整理或加購不增加該訊號人數
- 預購看目前有效明細，排除已刪除、數量為零；同一客戶多色多尺寸仍只算一位，件數另列
- 行為訊號取所選期間，正式預購取本期目前有效明細，兩個時間口徑在頁面明示
- 同分保留目前相對順序；每第 5 個位置優先安排一款沒有訊號的商品，降低熱門循環
- 無商品訊號時保留目前順序，少於 5 位觀察者顯示少量資料提示
- 6／3／10、每第五格及少於 5 位都是本次規則預設，沒有研究證明這組數字最適合本店；不宣稱為 AI 預測或成交機率
- 不使用停留時間、私有進價、客戶暱稱或私人資料排商品

套用必須包含所有上架商品且無重複；期間有商品上／下架或版本過期時拒絕舊草稿。保存版本與上次 ID 順序。新上架商品接在已套用順序後，分類與搜尋沿用同一相對順序；下架商品不顯示。

## 如何觀察銷售效果

業務成果依序看有效預購人數、件數及金額，再接上實際買到、付款與利潤。網站沒有自動收款資料，不把預購金額當實收。

後續若評估一次調整，先記錄目的、時間與想改善的指標，再觀察同樣口徑的結果。近期加入購物車的客人可能稍後才送單，要留合理觀察時間。接近截止的自然增加、選品變動及客群不同，都可能影響比較。

## 資料界線與尚未實作

- 只有登入後的第一方歷程，保留最近 180 天；無法回補以前、登入前離開與站外來源
- 造訪含重新整理，不等於獨立登入；加購操作不等於現存購物車；前景停留是估算
- 本版沒有自動發訊、好友比對、聯繫狀態、客服對話同步、營收歸因、完整漏斗報表、個人化排序、廣告名單或 A/B 實驗
- 不以觀察熱度代替有效預購採買，不更動商品價格、訂單快照、採購數量或活動開放狀態

上述未實作項目是研究的後續可能方向，未獲新增授權前不擴張範圍。
